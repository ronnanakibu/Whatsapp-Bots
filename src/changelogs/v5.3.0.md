# Changelog v5.3.0 — Discord Features, Lyrics Search & Custom Playlists Upgrade

## Features
- **Discord Bot Spotify-style Feature Suite**:
  - Implemented `.fav` (like current playing song), `!unfav <index>`, `!myfav` / `!favlist` (list favorites), and `!playfav <index | random | all>` (play favorites) directly in the Discord bot client.
  - Implemented `!recap [me|global|last|last me|<month>]` monthly wrapped statistics command for Discord integration.
  - Modified play request tracking: now formats Discord user JIDs as `message.author.id + '@discord'`, enabling the bot to record Discord play history in the database.
- **Lyrics Search Command (`.lyrics` / `!lyrics`)**:
  - Built a keyless, Open-Source lyrics search service using the public **LRCLIB** (`lrclib.net`) API.
  - Added `.lyrics` command for WhatsApp and `!lyrics` command for Discord.
  - Searches for the currently playing track if no query argument is given, and automatically truncates output to fit Discord/WhatsApp text limit regulations.
- **Custom Playlists Manager (`.playlist` / `.pl` & `!playlist` / `!pl`)**:
  - Created two new SQLite tables: `playlists` and `playlist_songs` (operating with primary key guards and cascaded deletes).
  - Built SQLite helper functions to create, edit, remove, fetch, play, and delete custom playlists.
  - Added `.playlist` / `.pl` command suite to WhatsApp and `!playlist` / `!pl` command suite to Discord supporting the subcommands: `create`, `add`, `remove`, `list`, `show`, `play`, and `delete`.

## Refactoring & Database Changes
- **SQLite Database Schema Updates**:
  - Appended initialization migrations for table definitions `playlists` and `playlist_songs` inside `src/services/db.js`.
- **Centralized Playlist API**:
  - Exported and integrated all database operations safely inside `src/services/radio.js`.
