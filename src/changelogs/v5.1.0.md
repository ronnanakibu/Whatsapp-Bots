# Changelog v5.1.0 — Spotify-like Favorites & Monthly Recap Upgrade

## Features
- **Spotify-like Favorites Command Set (`.fav`)**:
  - `.fav`: Adds the now playing song to favorites database (inserts to `favorites` table).
  - `.unfav <index>`: Removes a song from favorites by index.
  - `.myfav` / `.favlist`: Lists the user's favorite songs.
  - `.playfav <index | random | all>`: Plays/enqueues a favorite song.
- **Spotify-like Monthly Recap & Wrapped (`.recap` / `.wrapped`)**:
  - Displays monthly wrapped statistics.
  - `.recap` / `.recap global`: Displays overall radio statistics for the current month.
  - `.recap me`: Displays personal statistics for the user (requests, listening time, top songs) for the current month.
  - `.recap last`: Displays global statistics for the previous month.
  - `.recap last me`: Displays personal statistics for the previous month.
  - `.recap <1-12>`: Displays global statistics for a specific month.

## Bug Fixes
- **Queue Removal Fix**:
  - Fixed an issue where the `.queue remove` command was splicing a copy of the queue array rather than mutating the actual player queue inside `radioService`. Applied this fix to both WhatsApp command (`queue.js`) and Discord bot (`index.js`).
- **Global Queue Position Numbering**:
  - Changed queue position notification in `play.js` from `radioService.queue.length` to `radioService.queue.length + (radioService.currentTrack ? 1 : 0)`, aligning position output globally including the active playing song, avoiding constant `#1` display.
- **Database JID Matching**:
  - Fixed database tracking where `play.js` commands passed `ctx.pushName` as `requestedBy`, which skipped logging to the SQLite `requests` table due to lack of `@` sign. Now passes `ctx.sender` as JID and pushName separately, enabling correct play history, requests, and stats logging.
