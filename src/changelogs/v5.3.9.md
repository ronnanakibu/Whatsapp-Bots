# Changelog v5.3.9 — Concurrent Guest Streaming Support

## Bug Fixes
- **Allowed multiple anonymous/guest stream connections**:
  - **Issue**: When listeners accessed the radio stream via the web dashboard without explicit authentication (acting as guest / anonymous listeners), their connection was classified under JID `'anonymous'`. Since `'anonymous'` is a truthy string, the duplicate connection check in `addClient()` identified it as duplicate and immediately disconnected/kicked the previous guest listener. This meant only one guest listener could listen to the radio stream at a time; as soon as a friend connected, the original listener's connection was dropped.
  - **Fix**: Modified `addClient()` inside [radio.js](file:///d:/CE/JavaScript/BOTS/WABOT2.0/src/services/radio.js) to skip duplicate checking/kicking for `'anonymous'` connections. Duplicate session kicking is now strictly restricted to authenticated WhatsApp user JIDs, allowing unlimited guest dashboard listeners to stream concurrent live audio smoothly.
