# Release Notes v4.1.0 - Backend Production Foundation (v2.8 Rearchitecture)

This release implements the Backend v2.8 Production Foundation, standardizing the REST API contract, hardening streaming security, introducing Server-Sent Events (SSE) replay resilience, and performing clean startup session recoveries.

## Key Upgrades

### 🔒 Hardened Stream Security & Opaque Tokens
- **One-Time Consumption Stream Tokens**: Secured the `/stream` endpoint by replacing raw listener JIDs with short-lived opaque UUID stream tokens (TTL 5 mins). Tokens are consumed instantly on connection handshake and cleaned up periodically every 60 seconds.
- **SHA-256 User-Agent Hash Binding**: Binds stream tokens to the specific SHA-256 hash of the client's User-Agent string to prevent token session hijacking without exposing raw UA details in memory.
- **Multi-Tier Soft IP Validation**: Implemented a roaming-friendly NAT validation policy:
  - `INFO`: Logged on standard IP changes where UA/session remains valid (connection allowed).
  - `WARN`: Logged when the IP changes rapidly (>3 times in <5 minutes) for a listening session.
  - `ALERT`: Connection rejected with 403 Forbidden if both IP and UA change, indicating session theft.
- **Concurrent Stream Guard**: Enforced a strict single-connection limit per authenticated WhatsApp JID. Initiating a new stream connection automatically detects and terminates the older socket for that JID.

### 📶 SSE Event Buffer & Resilient Replays
- **Dual-Bounded Memory Buffer**: Maintained a running list of SSE events capped at 10 minutes TTL and a maximum size of 5,000 events to eliminate event-storm memory leaks.
- **Last-Event-ID Handshake Replay**: Standardized the `/events` endpoint to parse standard `Last-Event-ID` headers or query parameters, automatically replaying missed history events to recovering client connections.
- **Request Tracing & Correlation**: Enforced Request ID tracking using `REQ-YYYYMMDD-XXXXXXXX` headers. Specific client-initiated SSE events (`engagement:reaction`, `queue:update`, `engagement:favorite`) carry the triggering Request ID as a `correlationId`, while state-broadcast events (`track:start`, `listeners:update`) remain correlation-free.

### 🌐 Standardized REST API v2 Router
- **Enveloped REST Responses**: Standardized all route responses to wrap payloads in structured envelopes:
  - *Success Envelope*: `{ success: true, data: { ... } }`
  - *Error Envelope*: `{ success: false, error: { code, message } }`
- **JID/URI Parameter Normalization**: Added a key resolution helper (`resolveSongId`) to handle differences in URI percent encoding (`%3A` vs `:`) across route parameters, preventing database lookup mismatches.
- **Strict Production JWT Auth**: Enforced `authenticateJwt` across secure routes, binding actions to `req.user.jid`. Ensured that `DEV_BYPASS_AUTH` is strictly ignored when running in a `production` environment (`NODE_ENV === 'production'`).

### ⚙ Graceful Startup Presence Recovery
- **Bulk Listening Session Recovery**: Added a startup database execution query to automatically close dangling presence records (sessions where `left_at IS NULL` due to PM2 restarts or crash events) by setting them to the server boot time and calculating elapsed duration.
