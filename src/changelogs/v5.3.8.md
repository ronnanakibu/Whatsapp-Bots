# Changelog v5.3.8 — Radio Stream Fallback Download Pipelines

## Features & Bug Fixes
- **Hugging Face Downloader Fallback**:
  - Implemented an asynchronous Hugging Face downloader API fetch routine in [radio.js](file:///d:/CE/JavaScript/BOTS/WABOT2.0/src/services/radio.js) when real-time yt-dlp stdout pipe extraction fails.
  - The Hugging Face endpoint executes in an un-throttled environment to download the target stream audio into a local temporary file (`./storage/media/temp/radio_[timestamp].mp3`) and streams the local file directly using FFmpeg.
- **Local Full File yt-dlp Downloader Fallback**:
  - If Hugging Face is unreachable or fails, the radio service attempts to download the full audio track locally using `yt-dlp`'s file download mechanism (`--extract-audio --audio-format mp3`). Full file downloads are significantly more resilient to network dropouts and signature-induced extraction errors than stdout pipes.
- **Automatic Temp File Cleanup**:
  - Registered a file cleanup daemon inside the `.finally()` block of `#streamTrack` to ensure all generated temporary streaming files are deleted immediately after the song completes, is skipped, or fails, preventing storage leaks.
