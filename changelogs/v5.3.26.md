# Changelog - v5.3.26

## [5.3.26] - 2026-06-17

### Fixed
- **Dynamic Python Environment Mapping:**
  - Resolved `start.js` diagnostic false-positives by deferring diagnostics to run after the standalone Python binary has been mapped into `process.env.PATH`.
  - Added process-level export of `process.env.PYTHON_CMD` dynamically set to the resolved working Python executable (`python3`, `python`, or standalone `PYTHON_BIN`).
  - Modified `src/services/media.js` background removal invocations (`rembg`) to execute `"${pythonCmd}"` instead of hardcoded `python` to prevent command-not-found errors at runtime.
- **Pip Temp/Cache Storage Redirection:**
  - Redirected `process.env.TMPDIR` and `process.env.PIP_CACHE_DIR` globally in `start.js` to `./storage/media/tmp` inside the workspace, bypassing the tiny, restricted RAM-disk `/tmp` directory typical of Pterodactyl Docker containers that triggers `Errno 28: No space left on device` errors.
- **Auto-Restart on Connection Loss:**
  - Configured `src/core/bot.js` to terminate the process with exit code 1 (`process.exit(1)`) upon reaching maximum reconnection attempts (`MAX_RECONNECT_ATTEMPTS = 5`), allowing the Pterodactyl daemon (`wings`) or Docker restart policies to automatically restart the container rather than leaving the bot in a zombie state.
