# Release Notes v4.0.2 - FFmpeg Pipe and Realtime Streaming Fixes

This release resolves critical streaming issues where piping `yt-dlp` output to FFmpeg caused `FFmpeg exit code 183` ("Invalid data found when processing input").

## Bug Fixes

### 📻 Radio Service Stdin Pipe & FFmpeg Integration
- **Stream Verification Logic**: Replaced the `once('data')` listener used for checking if the `yt-dlp` stream is ready with a `'readable'` event listener and a direct check on `readableLength > 0`. This ensures that the first container header chunk of the stream is not consumed during validation, allowing FFmpeg to receive the full and intact stream.
- **FFmpeg Arguments Adjustment**: Removed the `-re` flag (realtime reading) from FFmpeg arguments for all piped inputs (`pipe:0`). This flag is only appropriate for direct URL streams and caused stream reading sync/timing errors when reading from a standard input pipe.
