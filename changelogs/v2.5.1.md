# Release Notes v2.5.1 - Client Connection Hardcoding & Route Fixes

This release addresses the unstyled dashboard rendering bug on the remote server and hardcodes backend socket and stream connections.

## What's New

### 🛠️ Client-side Host Hardcoding
- Hardcoded the socket client URL to `http://ap2.nzb.zelpstore.id:25637` in `useSocket.ts` to bypass dynamic origin parsing failure on remote environments.
- Hardcoded the SSE endpoint URL to `http://ap2.nzb.zelpstore.id:25637/events` in `useSSE.ts`.
- Hardcoded the live audio stream URL to `http://ap2.nzb.zelpstore.id:25637/stream` in `useAudioAnalyzer.tsx`.

### 🛡️ Express Static Asset Fallback Patch
- Refactored wildcard SPA fallback routing in `src/server/radio.js` to ignore static assets (folders containing `_next/` or files containing extensions like `.css`, `.js`).
- This stops the server from returning `index.html` for failed asset lookups, which was resulting in MIME-type validation failures and unstyled page renders.

### 📦 Automated Deployment Pipeline Upgrade
- Added build check and compilation routines for the BotOS Dashboard (`src/app/dashboard/`) inside `deploy.js`.
- Any changes to source files under `src/app/dashboard/` will automatically trigger a clean static Next.js production build (`npm run build`) and queue the output files for SFTP upload to the remote host.
