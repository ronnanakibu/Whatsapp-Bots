# Release Notes v3.1.7 - Seamless Discord Radio Streaming Pipeline

This release fixes the issue where the Discord bot ceases playing audio during track transitions or network hiccups, requiring users to manually kick the bot and make it re-join the voice channel.

## What's New

### 📻 Seamless Discord Radio Streaming & State Recovery
- **Stream Helper (`playStream`)**: Implemented a helper function that connects to the active audio stream `/stream` and runs it on the `audioPlayer`.
- **Track Transition Sync**: Added a listener to the global `radioService` for `track:start` events. When a new track starts, if the Discord bot is active in a voice channel, it automatically recreates the stream resource and starts playback immediately.
- **Robust Idle/Disconnect Recovery**: Enhanced the `AudioPlayerStatus.Idle` event listener. If the player goes idle while `radioService` is still playing, the bot waits 1 second and automatically reconnects to the stream.
- **Auto-Error Recovery**: Enhanced the `error` event listener to log the exception and automatically schedule a stream reconnection 2 seconds later if the radio is active.
- **Join/Play Command Re-activation**: Improved the `!join` and `!play` commands so that if the bot is already in the channel but silent/idle, running the command again will instantly refresh the stream and resume playing without needing to kick/rejoin.
- **Version Bump**: Bumped core version to `3.1.7`.
